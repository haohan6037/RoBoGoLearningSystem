# RoBoGo 课程管理系统升级改造需求

- 文档版本：V1.0
- 编写日期：2026-08-10
- 适用系统：`apps/learning-portal`
- 文档性质：现有系统升级需求基线

## 1. 项目背景

现有 RoBoGo Learning Portal 已具备学生、班级、课次、授课、考勤和课件管理的 MVP 能力，但教师端仍以系统内部数据对象作为菜单入口，页面职责交叉，导航和视觉规范不统一。竞赛课相关能力则部分存在于独立工程笔记工作树中，尚未进入当前主课程管理系统。

本次升级的目标不是推翻现有功能，而是在保留课件、课堂和学生管理能力的前提下，重新建立清晰的信息架构，并逐步补齐教师管理、竞赛队伍、工程笔记集成和阶段成果展示。

## 2. 升级目标

1. 将教师端菜单重组为工作台、系统设置、常规课、竞赛课和课件管理。
2. 让菜单名称、页面职责和教师实际工作流程一致。
3. 消除课程管理、授课、考勤和课件分配之间的重复入口。
4. 建立统一页面壳层、视觉规范、交互反馈和响应式导航。
5. 在不重写既有工程笔记功能的前提下，将其纳入竞赛课体系。
6. 为后续课程模型、队伍模型和阶段成果模型扩展预留稳定边界。

## 3. 用户与使用场景

### 3.1 系统管理员

- 管理教师账号及启停状态。
- 查看和维护班级、学生等基础数据。
- 根据后续权限模型配置教师可管理范围。

### 3.2 教师

- 管理班级和学生。
- 创建常规课程计划并生成具体课次。
- 为课次配置课件并进入现场授课。
- 管理竞赛队伍、查看工程笔记和发布阶段成果。
- 使用课件库及 3D 课件制作工具。

### 3.3 学生

- 查看当前课程、课程安排、复习课件和考勤记录。
- 在竞赛课中参与队伍工程笔记和阶段成果沉淀。

## 4. 目标菜单结构

### 4.1 工作台

- 数据概览
- 今日课程
- 待处理事项
- 常用功能快捷入口

### 4.2 系统设置

- 教师管理
- 班级管理
- 学生管理

### 4.3 常规课

- 课程管理
- 授课

### 4.4 竞赛课

- 队伍管理
- 工程笔记
- 阶段成果展示

### 4.5 课件管理

- 课件库
- 3D 课件制作

考勤不再作为独立一级入口。课程历史考勤归入课程管理的课次详情，实时考勤归入授课页面。

## 5. 功能需求

### 5.1 工作台

| 编号 | 需求 | 优先级 |
|---|---|---|
| DASH-01 | 显示学生、班级、近期课程、课件和竞赛队伍等核心统计 | P1 |
| DASH-02 | 显示当天及下一节待授课程，可直接进入授课 | P1 |
| DASH-03 | 显示无课件课程、未完成笔记、待确认成果等提醒 | P2 |
| DASH-04 | 指标卡可进入对应业务列表，不只展示数字 | P1 |

### 5.2 系统设置

#### 教师管理

| 编号 | 需求 | 优先级 |
|---|---|---|
| SYS-T-01 | 创建、编辑、停用和恢复教师账号 | P1 |
| SYS-T-02 | 显示教师姓名、登录账号、状态和负责班级 | P1 |
| SYS-T-03 | 支持重置教师密码 | P1 |
| SYS-T-04 | 预留管理员、教师等权限角色扩展能力 | P2 |

#### 班级管理

| 编号 | 需求 | 优先级 |
|---|---|---|
| SYS-C-01 | 创建、编辑、归档和恢复班级 | P1 |
| SYS-C-02 | 添加、移除和查看班级学生 | P1 |
| SYS-C-03 | 班级成员关系与课程时间计划分离 | P1 |
| SYS-C-04 | 显示班级当前人数及关联课程 | P2 |

#### 学生管理

| 编号 | 需求 | 优先级 |
|---|---|---|
| SYS-S-01 | 保留现有学生创建、编辑和密码管理 | P0 |
| SYS-S-02 | 增加停用、恢复和状态筛选 | P1 |
| SYS-S-03 | 支持查看所属班级、常规课和竞赛队伍 | P1 |
| SYS-S-04 | 危险操作必须二次确认并提供明确结果反馈 | P0 |

### 5.3 常规课

#### 课程管理

| 编号 | 需求 | 优先级 |
|---|---|---|
| REG-C-01 | 集中管理课程计划、课次、课件配置和历史记录 | P0 |
| REG-C-02 | 课程列表支持按班级、状态、日期和关键词筛选 | P1 |
| REG-C-03 | 课程详情显示基础信息、课次、课件和考勤摘要 | P1 |
| REG-C-04 | 支持按周期生成课次，并能查看生成结果 | P0 |
| REG-C-05 | 支持为课次配置理论、搭建或通用课件 | P0 |
| REG-C-06 | 完成、取消等状态操作应收纳在课次详情或操作菜单中 | P0 |
| REG-C-07 | 历史考勤在课次详情查看，不再保留独立侧边菜单 | P0 |

#### 授课

| 编号 | 需求 | 优先级 |
|---|---|---|
| REG-L-01 | 默认显示今日待授课程和正在进行的课程 | P0 |
| REG-L-02 | 支持进入课程后控制等待、理论、搭建三个阶段 | P0 |
| REG-L-03 | 默认禁止阶段倒退；如需倒退必须明确确认 | P0 |
| REG-L-04 | 实时显示学生考勤、位置异常和手动签到操作 | P0 |
| REG-L-05 | 在同一工作区显示当前阶段对应课件 | P0 |
| REG-L-06 | 避免在课程管理和授课页面同时提供相同阶段控制 | P0 |
| REG-L-07 | 已完成、已取消课程不进入默认授课选择列表 | P1 |

## 6. 体验与视觉需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| UX-01 | 所有教师页面必须共用一个页面壳层和一份菜单配置 | P0 |
| UX-02 | 一级菜单支持分组，二级菜单支持展开、收起和当前项高亮 | P0 |
| UX-03 | 页面名称、按钮和状态文案统一使用中文 | P0 |
| UX-04 | 建立主操作、次操作、危险操作三个明确等级 | P0 |
| UX-05 | 删除、取消课程等危险操作不得与主操作并列强调 | P0 |
| UX-06 | 表单默认收起或使用抽屉/弹窗，列表页保持任务聚焦 | P1 |
| UX-07 | 列表提供筛选、空状态、加载状态、失败状态和成功反馈 | P1 |
| UX-08 | 平板和手机端使用折叠菜单，不把完整侧边栏直接堆到内容上方 | P1 |
| UX-09 | 页面状态应反映在 URL 中，支持刷新、收藏和浏览器前进后退 | P1 |
| UX-10 | Emoji 只作辅助，不作为主要图标规范 | P2 |

## 7. 非功能需求

1. 保留当前 FastAPI 和 SQLite/PostgreSQL 双数据库方向。
2. 第一阶段菜单改造不得改变现有 API 行为或历史数据。
3. 新增数据模型必须提供可重复执行的迁移方案，不继续无限扩展启动时 `ALTER TABLE`。
4. 教师、队伍和成果相关写操作必须进行权限校验。
5. 工程笔记必须保留学生作者身份和原始文字，不使用自动改写或自动合并。
6. 页面拆分后应可进行最小范围的单元或浏览器回归验证。
7. 不得直接暴露当前本地 MVP 到互联网环境。

## 8. 范围边界

### 8.1 本次升级包含

- 教师端菜单和页面信息架构重构。
- 现有常规课、课件和授课页面重新归类。
- 教师管理补齐。
- 工程笔记工作树集成。
- 队伍管理和阶段成果展示。
- 页面视觉和交互规范统一。

### 8.2 本次升级暂不包含

- 公开家长门户。
- 互联网生产部署。
- 支付、报名和商业订单。
- 自动改写学生工程笔记。
- Assembly Studio 内部 3D 编辑能力重构。
- 全新的移动端原生应用。

## 9. 总体验收标准

1. 教师端仅显示确认后的目标菜单结构，不再出现旧的平铺导航。
2. 每个现有功能都有唯一、可理解的业务归属。
3. 学生、班级、课程、课次、队伍和课件概念在页面和数据设计中不混用。
4. 教师可从今日课程进入授课，无需在全部历史课次中查找。
5. 授课阶段、考勤和当前课件集中在一个工作区。
6. 独立工程笔记能力成功接入主课程管理系统，原有作者保护和发布流程不回退。
7. 桌面、平板和手机的菜单均可正常使用。
8. 关键页面刷新后可恢复，浏览器前进后退行为正确。
9. 原有课件创建、编辑、预览和课堂打开流程通过回归验证。
10. 所有升级均有明确验证记录和回滚方式。
