# RoBoGo 课程管理系统升级开发计划书

- 文档版本：V1.0
- 编写日期：2026-08-10
- 关联需求：`RoBoGo_Learning_Portal_Upgrade_Requirements.md`
- 计划原则：先信息架构，后功能补齐；先复用已验证能力，后开发新模块

## 1. 开发目标

在保持现有 learning-portal 可运行、现有课件和授课流程可回归的前提下，分阶段完成教师端导航重构、常规课体验优化、竞赛课能力集成和新增功能建设。

## 2. 实施原则

1. 不在现有 Assembly Studio 未提交改动上做无关修改。
2. 每个阶段形成可独立验证、可回滚的交付点。
3. 菜单重构阶段不同时修改数据库。
4. 工程笔记优先从独立工作树集成，不复制重写。
5. 单次实现尽量控制在三个直接相关文件内；超出时先说明模块拆分原因。
6. 所有危险操作、权限和数据迁移在实施前单独确认。

## 3. 阶段划分

### 阶段 0：基线与运行环境恢复

目标：建立可信的开发和回归基线。

任务：

- 修复或重建项目约定的 Python 运行环境。
- 解决 Python 版本与锁定依赖不兼容问题。
- 验证 SQLite 预览和现有数据库配置。
- 记录当前菜单、API、页面截图和关键流程。
- 确认主工作区与工程笔记工作树的分支、提交和未提交文件。
- 更新根交接文档，使其反映当前真实状态。

验证：

- `npm run start:learning` 可以按文档启动。
- `/api/health` 返回 200。
- 教师演示账号可以登录。
- Overview、Students、Classes、Sessions、Classroom、Material Library 可打开。

交付物：

- 可复现的启动说明。
- 基线验证记录。
- 更新后的交接文档。

### 阶段 1：菜单与公共页面壳层

目标：在不改变后端行为的情况下完成信息架构重组。

任务：

- 建立唯一的教师菜单配置。
- 建立公共 `TeacherPortalShell` 渲染函数。
- 删除各页面重复的侧边栏和顶栏模板。
- 增加一级分组、二级菜单、展开状态和当前项高亮。
- 将旧页面映射到新菜单：
  - Students → 系统设置 / 学生管理
  - Classes → 系统设置 / 班级管理
  - Sessions → 常规课 / 课程管理
  - Classroom → 常规课 / 授课
  - Material Library → 课件管理 / 课件库
  - Assembly Studio → 课件管理 / 3D课件制作
  - Attendance → 课程管理内部入口
- 统一中文页面名称和返回行为。
- 为页面状态建立可恢复的 URL 或 hash 路由。

验证：

- 所有菜单项可达且只有一个当前高亮项。
- 刷新后仍停留在原页面。
- 浏览器前进、后退正确。
- 旧功能 API 请求数量和结果没有异常变化。
- Assembly Studio 外链在所有教师页面保持一致。

回滚：

- 仅回滚公共壳层和菜单配置，不涉及数据库。

### 阶段 2：视觉规范和基础体验统一

目标：解决页面密度、操作层级和响应式问题。

任务：

- 建立页面标题区、工具栏、列表、表单、状态标签和空状态规范。
- 将主要内联样式迁移为语义化 CSS 类。
- 统一主按钮、次按钮、文字按钮和危险按钮。
- 将创建/编辑表单改为统一的折叠区、抽屉或弹窗模式。
- 为平板和手机增加可收起菜单。
- 统一中文文案、状态名称和日期时间格式。
- 减少无意义的大卡片和阴影，提高列表信息密度。

验证：

- 1280px、1024px、768px、390px 四个典型宽度下无横向溢出。
- 主操作和危险操作视觉层级明确。
- 键盘可聚焦菜单、表单和弹窗。
- Students、Classes、Sessions、Classroom、Material Library 视觉一致。

### 阶段 3：常规课流程整理

目标：把课程管理和现场授课拆成两个清晰流程。

任务：

- 课程管理页增加日期、班级、状态筛选。
- 建立课程/课次详情，收纳课件配置、考勤历史和状态操作。
- 从课程列表移除现场阶段控制按钮。
- 授课页默认显示今日和正在进行的课程。
- 隐藏已取消课程，历史课程单独筛选。
- 限制阶段从等待 → 理论 → 搭建顺序前进。
- 阶段回退需要明确确认并记录原因，或在首版完全禁止。
- 统一授课页内的实时考勤、手动签到和课件打开流程。

验证：

- 教师可在三步内从工作台进入今日授课。
- 同一个阶段控制只在授课页出现。
- 阶段不会被无确认地倒退。
- 当前课程、历史课程和取消课程不会混淆。
- 学生端 5 秒轮询和教师端 8 秒轮询行为不回退。

### 阶段 4：系统设置补齐

目标：形成完整的教师、班级和学生基础数据管理。

任务：

- 新增教师管理模型、API 和页面。
- 增加教师停用、恢复和密码重置。
- 增加学生停用、恢复和状态筛选。
- 增加班级归档、恢复和成员移除。
- 将班级成员信息与课程周期计划分离。
- 定义管理员与教师的权限边界。

风险：

- 涉及认证、权限和数据模型，属于高风险阶段。
- 开始前必须确认管理员角色和教师可见范围。

验证：

- 被停用账号不能登录。
- 教师只能访问授权数据。
- 班级归档不会删除历史课程、考勤和工程笔记。
- 成员移除不会破坏历史记录归属。

### 阶段 5：工程笔记集成

目标：将独立工作树中已验证的竞赛能力安全迁入当前系统。

任务：

- 对比主工作区与 `codex/engineering-notebook-mvp` 的数据库、模型、API 和前端差异。
- 先迁移 Engineering Team、成员角色和赛季边界。
- 再迁移单记录工程笔记、附件、提议、确认、发布和 PDF 导出。
- 将队伍管理和工程笔记接入竞赛课菜单。
- 保持常规课堂笔记与竞赛工程笔记分离。

必须保留：

- 每名学生、每支队伍、每节课一个可持续编辑记录。
- 一个 Save 操作。
- 学生原文不被 AI 改写。
- 来源作者确认后才由 Notebooker 发布。
- 教师只读监督。

验证：

- 原独立工作树的工程笔记 API 测试全部通过。
- 同一学生/队伍/课次不能产生重复笔记。
- 保存后仍可继续编辑。
- 发布记录和 PDF 导出结果确定且可重复。
- 常规课现有课程和课件回归通过。

### 阶段 6：阶段成果展示

目标：建立竞赛过程中的可筛选成果展示区。

任务：

- 定义阶段成果模型和草稿/发布状态。
- 支持标题、阶段、说明、附件和关联对象。
- 支持关联已发布工程笔记、媒体或 3D 项目。
- 建立教师管理视图和学生展示视图。
- 增加队伍、赛季、阶段筛选。

验证：

- 草稿不会出现在展示页。
- 发布、撤回和附件访问均有权限校验。
- 删除或归档队伍不会破坏历史成果。

### 阶段 7：完整回归与交付

任务：

- 执行教师端、学生端、竞赛课和课件管理关键流程回归。
- 检查桌面、平板和手机布局。
- 检查 SQLite 与 PostgreSQL 兼容性。
- 更新需求、设计、交接和启动文档。
- 记录已知限制、回滚点和下一阶段建议。

## 4. 推荐迭代顺序

| 迭代 | 内容 | 风险 | 是否涉及数据库 |
|---|---|---|---|
| Iteration 1 | 运行基线、公共壳层、菜单重组 | 低 | 否 |
| Iteration 2 | 视觉规范、响应式、中文化 | 中 | 否 |
| Iteration 3 | 常规课课程管理与授课体验 | 中 | 尽量否 |
| Iteration 4 | 教师/班级/学生系统设置补齐 | 高 | 是 |
| Iteration 5 | 工程笔记和队伍管理集成 | 高 | 是 |
| Iteration 6 | 阶段成果展示 | 高 | 是 |
| Iteration 7 | 全量回归、文档和交付 | 中 | 否 |

## 5. 工作分解与责任边界

### 前端

- 菜单配置、路由和公共页面壳层。
- 页面布局、组件状态和响应式体验。
- 课程管理、授课、系统设置和竞赛页面。
- 危险操作确认、加载、错误和成功反馈。

### 后端

- 教师、权限、队伍和阶段成果模型。
- 课程/班级边界调整所需 API。
- 工程笔记 API 合并和数据迁移。
- 权限、状态转换和历史数据保护。

### 验证

- API 定向测试。
- JavaScript 语法和页面路由检查。
- 浏览器关键流程回归。
- 数据迁移前后数量与关联完整性检查。

## 6. 质量门槛

每个迭代完成必须满足：

1. `git diff --check` 通过。
2. 相关 API 或脚本测试通过。
3. 真实页面可打开并完成本迭代关键流程。
4. 未修改无关 Assembly Studio 文件。
5. 已记录改动文件、验证结果、限制和回滚方式。
6. 若同一问题连续三次验证失败，停止修改并提交失败报告。

## 7. 主要风险及应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 主工作区与工程笔记工作树存在差异 | 合并时覆盖功能 | 先做三方差异清单，再按模型/API/UI分层迁移 |
| 班级与课程概念未最终确认 | 数据模型返工 | 菜单阶段先不改库，模型阶段单独确认 |
| 单体 `app.js` 继续膨胀 | 页面难维护 | 先提取公共壳层，再逐页面拆分模块 |
| 当前 Python 环境失效 | 无法稳定验证 | 阶段0先修复可复现运行环境 |
| 权限模型仍是本地 MVP | 数据越权风险 | 教师管理实施前完成角色和范围设计 |
| 启动时迁移方式不可控 | 数据升级风险 | 新增正式迁移机制和备份验证 |

## 8. 里程碑完成定义

- M1：新菜单上线，所有旧功能可从新结构访问。
- M2：教师端视觉和响应式体验统一。
- M3：常规课形成“课程管理 → 授课”的完整主路径。
- M4：教师、班级和学生管理形成完整闭环。
- M5：竞赛队伍和工程笔记进入主系统且原有验证不回退。
- M6：阶段成果可管理、发布和展示。
- M7：完整回归通过，交接文档与真实环境一致。
